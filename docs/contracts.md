# Preliminary foundation contracts and handoff

These interfaces are a review proposal, not a completed Phase 0 handoff; see [the gate audit](phase0-gate.md). The integration owner decides when the issue's Phase 0 exit gate passes; production feature implementations and native v1 qualification belong to later phases. See the [workstream handoff](foundation-handoff.md). The integration owner owns all headers, schema, CMake, dependency selection and CI. Future workstreams own their code under `lib/core` and `src/cli` (DSP); `lib/library` (storage/jobs); `src/desktop` (shared presentation); and `lib/capture/{pipewire,coreaudio,wasapi}` plus corresponding `src/desktop/platform` adapters. Propose shared changes before depending on them.

## Audio and timing

`AudioBlock` is a borrowed view of interleaved float PCM; a source normalizes to float and declares rate, channel count and layout. A consumer must copy before the callback returns; `AudioQueue` supplies bounded preallocated SPSC transfer with one reserved slot. The callback may only copy into such storage and record timing/status. Each source epoch identifies a continuous format and timeline. Frame 0 is its origin; seeks, restart, device or format changes require a new epoch. Frame offsets are authoritative, and monotonic nanoseconds are capture-clock anchors, not musical event times. `AudioClockAnchor` and `frame_to_monotonic_ns` map positions in the same epoch using checked integer arithmetic; the result is a point estimate, not drift or latency compensation. Backends must document anchor validity, clock accuracy and drift before integration. Overflow drops a whole block, counts complete frames and marks the next accepted block discontinuous. Consumers may drain stale backlog and must reset/reacquire after any gap or discontinuity. The consumer-owned `StreamContinuity` identifies acquisition, contiguous blocks, and reacquisition; it rejects malformed blocks and a format change within an epoch without advancing state. `stop()` quiesces callbacks before returning, and callers must stop before destruction. A capture callback must never call `status()`, allocate, log, lock, do DSP, or call UI/database. Platform adapters now feed the shared CLI/GUI presentation path; native device qualification remains platform-specific and must still be captured on supported hosts.

## Estimators and publication

The provisional strategy ports consume observed audio on worker threads; reset on epoch/format changes or gaps. Scores are uncalibrated strengths, not probabilities. `EventTime` is an epoch and frame, separate from snapshot publication time and known delay. `SnapshotPublisher` provides immutable latest-value handoff with bounded event/candidate counts and text lengths. A single worker must supply complete ordered histories, advance its acquisition token on invalidation and clear publication on stop, silence or error; readers may retain old copies and must not treat them as current after invalidation. It allocates and may lock, so never belongs in a capture callback. The GUI owns its presentation adapter and update cadence; integration with a real live publisher is still outstanding. `TrackingMachine` implements stopped/silent/acquiring/tracking/reacquiring/error transitions and rejects stale acquisition tokens. The worker owns it; callers must clear stale displayed values when evidence is invalidated. File replay uses it with a provisional one-second, peak-below-0.0001 silence rule. Thresholds are tuning choices, not calibrated guarantees; live adapters and presentation publication must integrate and test their own lifecycle. `TempoTracker` currently exposes only BPM and beat count, and does not yet implement the broader strategy port or timestamp beats. `reduce_loudest_channel` implements the provisional block-energy channel selection in caller-owned worker buffers; it rejects malformed/non-finite PCM and preserves anti-phase stereo. It does not resample or prevent switching artifacts.

## Jobs and storage

`AnalysisStore` describes a worker-owned boundary, not a SQLite implementation. The identity includes content hash, engine/config version and analysis mode. A store must ensure writes are serialized, compare pre/post file versions and validate identity before atomically publishing completed results. Cancellation and failures cannot replace a successful cached run. Fast stat checks, hashing policy, migration/schema and race-free transactional behavior still need an implemented, reviewed contract and acceptance tests; the current interface alone cannot guarantee them. No database calls belong on GUI/audio threads.

## Replay and limitations

`FileReader` is a worker-owned, synchronous pull source; its returned PCM span borrows caller storage. A successful seek advances the file epoch, cancellation is checked before I/O, and a decoder failure invalidates the reader. It has no live monotonic anchor and cannot interrupt an already-blocking read. `beatglass-tool --replay <file>` uses this reader to feed blocks faster than real time through the same incremental tracker and prints estimates after observed blocks; it does not simulate wall clock scheduling or a real capture device. See tests for generated silence, clicks and anti-phase stereo. Synthetic fixtures do not establish accuracy on full mixes. Generated file-reader tests cover seek, EOF, pre-read cancellation and sample-rate changes across epochs; the CLI Library adds persistent identities, cache admission, retry recovery and stale-source verification. Live capture, device interruption and bounded snapshot publication are integrated through the shared presentation path, while native behavior still requires qualification on actual supported hosts. Platform minimum versions, decoder/codec coverage, resampling, packaging, dependency licenses and complete cross-platform native qualification remain incomplete.
